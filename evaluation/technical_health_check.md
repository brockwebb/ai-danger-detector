## Major Technical Findings

### 1. The interactive application does not compile

File: `applications/interactive_assessment.py`

The `compare_domains` function is dedented out of the class at line 88, then later methods are indented as if still inside a class. Python reports an `IndentationError` at line 137.

Impact: the user-facing interactive app cannot run or be imported.

### 2. `applications/__init__.py` imports a missing module

File: `applications/__init__.py`

It imports:

```python
from .sensitivity_analyzer import SensitivityAnalyzer
```

But the actual file is:

```text
applications/sensitivity_tool.py
```

Impact: importing `applications` fails before reaching the interactive assessment code.

### 3. README claims exceed implementation

The README says users can describe intended AI use in natural language and the tool will classify the scenario. Current code requires numeric inputs: harm, complexity, and error rate.

The README also claims rigorous analytical models and scientific validation. The repo contains parameter sweeps and synthetic validation scaffolding, but no empirical validation dataset, expert calibration protocol, or source-backed parameter derivation.

### 4. No reproducible environment

There is no dependency manifest. Most modules require packages such as `numpy`, `pandas`, `matplotlib`, `seaborn`, `tqdm`, `scipy`, and `scikit-learn`, but these are not declared.

Impact: a new user cannot run the project without reverse-engineering dependencies.

### 5. The scoring model saturates heavily

Using a small grid of harm values 1-10, complexity values 1-10, and error rates 5%, 15%, 30%, and 50%, the domain profiles produce many capped scores.

```text
medical: mean=8.54, expert_share=76.0%, saturated_share=62.3%, basic_share=1.8%
legal: mean=8.50, expert_share=74.5%, saturated_share=59.5%, basic_share=1.5%
creative: mean=3.09, expert_share=0.0%, saturated_share=0.0%, basic_share=49.0%
statistical: mean=7.23, expert_share=55.0%, saturated_share=24.5%, basic_share=4.8%
financial: mean=8.81, expert_share=81.2%, saturated_share=63.0%, basic_share=1.0%
educational: mean=6.60, expert_share=43.5%, saturated_share=13.0%, basic_share=5.8%
```

Impact: for several high-stakes domains, the model often says "10" and loses ranking power. That may be defensible as a warning, but it is not a nuanced detector.

### 6. Validation is mostly self-referential

The validation modules test whether the formula behaves as expected under synthetic assumptions. That is useful for model hygiene, but it does not validate whether the domain weights or expertise levels are correct.

Impact: do not describe the current project as scientifically validated.

### 7. ML layer appears unnecessary

The machine learning modules train models on synthetic labels generated by the same hand-built formula. That means ML mostly learns the formula, not real-world safety or expertise requirements.

Impact: this adds complexity without adding credibility. For a refresh, remove or de-emphasize ML unless real calibration data exists.

### 8. Generated/notebook artifacts leak into the tree

The working tree contains `.ipynb_checkpoints` directories ignored by git, and `.DS_Store` is tracked.

Impact: minor, but it reinforces that this is a notebook-era prototype rather than a polished repository.

## What Works

- `core_model.model_definition.expertise_required` runs with the standard library.
- `data_generation/calculator.py` runs as a script because it avoids importing the heavier package `__init__`.
- The conceptual model is simple enough to explain and test.
- Domain profiles are easy to inspect and modify.

## Technical Recommendation

Do not repair every module. First choose a smaller revived shape.

Minimum cleanup for publication:

1. Add `pyproject.toml` or `requirements.txt`.
2. Fix `applications/__init__.py`.
3. Fix indentation in `applications/interactive_assessment.py`.
4. Add a smoke test for calculator and app import.
5. Add tests for monotonicity and score boundaries.
6. Replace unsupported README claims.
7. Remove or archive the ML layer unless there is real data.

Best technical path: rebuild as a small library plus CLI or static web demo, not a sprawling ML package.
